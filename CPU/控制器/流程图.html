控制信号的门电路 —— RegWrite = ~op₂ · ~op₁

ADD/SUB/LD/AND/OR 都要写寄存器（op=000/001/010/110/111），其反面就是 ST/BEQ/JMP
op₂ op₁
RegWrite =1
拨 op₂=0, op₁=1（= ST 指令）：两个反相器都亮、AND 输出 0 → RegWrite 灭，存储器写入使能才会亮（对照 L2 第 011 行）。
  • 每一路控制信号都是操作码位的布尔函数 —— 硬布线控制器的本质
  • RegWrite=1 的指令（ADD/SUB/LD/AND/OR）在 op₂ op₁ 上没有统一的 1 位区分 → 实际用更多位
  • 门电路管数：2 个 NOT（4 管）+ 1 个 AND（6 管）= 10 管，就生成了一路控制信号

微程序控制器 Microprogram —— 控制字存在"控制存储器"里

每条机器指令 = 一段微程序；填一个微地址（0~7），读出对应的控制字

按「微步进」：μPC → 读出微指令 → 控制字点亮 → 下一地址写回 μPC，循环往复。一条机器指令 = 一段微程序。
  • 控制存储器里存的是"控制字的位串" —— 修改它 = 改变 CPU 行为，不用改电路
  • 每条微指令自带"下一微地址"字段 → 微程序可以顺序执行、也可以条件分支
  • x86（Intel/AMD）至今用微程序实现复杂指令；RISC（ARM/RISC-V）基本全硬布线
最后一层 ↓ 两种实现方式的对比与晶体管代价
L5

硬布线 Hardwired vs 微程序 Microprogrammed

同一个"译码 + 发信号"任务，两种截然不同的实现哲学
指令数 N16 条
硬布线管数 ≈— 微程序 ROM 位 ≈—
拖动"指令数 N"滑块：指令越多，硬布线的组合逻辑管数平方级膨胀，而微程序只是 ROM 变长 —— 这就是 CISC 走微程序路线的根本原因。
  • 硬布线：opcode 直通组合逻辑（L3 那种门电路阵列），速度极快，但指令集复杂时电路爆炸
  • 微程序：把控制字当数据存 ROM（L4），指令集可以很复杂，代价是每步要读一次存储器
  • 至此全链条打通：晶体管 → 门 → 译码器 → 控制信号 → 微程序 → 五阶段循环，CPU 的"指挥系统"每一层都摸过了
四页一套：硅→寄存器 · ALU · 门→晶体管 · 控制器 —— 数据通路 + 控制通路，CPU 的两大主干都在你手里拨过了。
